# PlaizierOS 21.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship PlaizierOS 21.0: the Silver Night home from the design canvas, Jarvis running on its own brain (Claude, with Gemini as a switch) without the laptop, and a home screen that stays the home screen.

**Architecture:** Builds on 5.8.2 (Kotlin + Compose launcher, package `com.wolfram.lumen`). The look changes in place: the baked background (Scenes.kt) gets the Silver Night palette, and SceneHome is relaid as greeting, a lit-glass favourites row and a row of circles, with a resting state. Jarvis keys come in through the phone remote and are stored with Android Keystore; the assistant picks Haiku or Opus per question and caches its prompt. An accessibility service is the second home lock. There is no Android SDK in the authoring sandbox: GitHub Actions is the compiler and the test runner.

**Tech Stack:** Kotlin 2.1, Jetpack Compose (BOM 2024.12.01), AGP 8.7.3, JUnit 4 for JVM unit tests, GitHub Actions.

**Spec:** Research doc "PlaizierOS 6: research and upgrade plan" (https://claude.ai/artifact/G4Zgt5TnMuUw1HyMvi7qVW) and the design canvas (https://claude.ai/artifact/Lt5bLUkDjMweRD4ZY4w5N8). 21.0 covers the doc's build-order stages Foundation, Home and Jarvis core; the other upgrades follow in 21.x releases.

## Global Constraints

- versionName `21.0`, versionCode `22`; the app is called PlaizierOS everywhere a person reads it, and the assistant is called Jarvis.
- Palette: Night `#0A0C10`, Slate `#1F242C`, Steel `#454C56`, Mist `#767D87`, Silver `#F4F6F8`, Signal `#FF6A5C`. Colour comes only from the apps.
- Sizes are dp on the 960 × 540 dp screen (1 dp = 2 px at 1080p).
- No API key in the APK, in GitHub or in chat: keys arrive from the phone remote and are stored encrypted with an Android Keystore AES-GCM key. `/api/state` never returns a key.
- Models: `claude-haiku-5-5` (default) and `claude-opus-5-5` (hard questions); Gemini model id lives in `LumenConfig.GEMINI_MODEL`. Header `anthropic-version: 2023-06-01`.
- Strava data never goes to an AI (no Strava code in this release).
- Commits end with the session attribution lines.

## Review Focus

1. A key pasted with spaces or a newline from the phone must still be accepted (trimmed), and a Gemini key pasted in the Claude field must be refused with a clear message. (Task 4 test `keysAreTrimmedAndChecked`.)
2. No key at all, or the Keystore failing on this TV: Jarvis must still answer built-in TV commands and say how to add a key, never crash. (Task 4 test `missingKeyLoadsNull` + Task 5 fallback path.)
3. The resting state must never swallow a key while a panel, page or the welcome animation is open. (Task 3 test `restsOnlyOnBareHome`.)
4. The Home guard must not loop: when PlaizierOS itself is in front, a stock-launcher window event must not relaunch it. (Task 6 test `guardIgnoresOwnPackage`.)
5. A long or Dutch question ("waarom…", "leg uit…") must reach Opus; a short command must stay on Haiku. (Task 5 test `picksModelByQuestion`.)
